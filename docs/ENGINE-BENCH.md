# ★ 第一个明显瓶颈（已定位到具体机制）

**现象**：3.8 m² 的厨房里，厨柜台面（1,700x600）**永远放不下**，
求解器最后交出一个没有台面的厨房，而报告一句都不提。

**定位过程**（scripts 里的诊断）：

1. 单独给厨房 4 件家具跑 24 种锚定顺序（≤4 件会穷举全部排列），得到 **4 种结果**：
   ~~~
   结果 counter                硬伤0 漏放罚分 97   （6 个顺序）
   结果 fridge,stove,washer    硬伤0 漏放罚分 73   <-- 求解器选这个
   结果 fridge,stove,washer    硬伤1 漏放罚分 74
   结果 stove,washer           硬伤0 漏放罚分 109
   ~~~
2. 也就是说：**台面先落 → 它一个人把厨房封死 → 3 件电器全放不下（罚 97）；
   台面不落 → 3 件电器都放得下（罚 73）。73 < 97，求解器「正确地」选了没有台面的厨房。**

**根因不是评分，是几何模型**：

- 厨房可用 2,120 x 1,735 mm。
- `FRONT_CLEARANCE["kitchen_counter"] = 900`，而 **`anchor_fronts` 把「已放家具正前方 900mm」
  当成硬禁区**，候选格一律不准压上去。
- 于是台面要占用 1,700 x (600+900) = 2,550,000 mm²，占掉厨房 69%，
  剩下的 235mm 深条带放不下任何一件 600 深的电器。
- 实测台面在 1,470 个候选格里只有 **22 个**可行（1.5%），而雪柜 358 个、灶台 398 个、洗衣机 426 个。

**为什么这是「明显瓶颈」**：真实香港 3.8 m² 厨房的正解是
**台面、灶台、雪柜排成一列，共用同一条 900mm 通道** ——
一个通道服务三件设备。而引擎要求**每件家具各自独占一条 900mm 净空**，
三件就是三条互不重叠的净空带。这在 3.8 m² 里几何上不可能。

这不是参数没调好，是**净空模型本身错了**：
把「人站着用的通道」建模成了「每件家具私有的矩形领地」。

## 下一轮要验证的修法

1. **净空区改成可以互相重叠的软代价**（人是站在同一条通道里用台面、灶台和雪柜的）。
2. **厨房排成一列**：给 kitchen_counter / stove / fridge 之间加「肩并肩」关系（同一面墙、相邻）。
3. 台面的净空应该是**沿台面的长边**，不是整块矩形。

改完用同一个基准重跑，看「1 全部放得下」能不能变 PASS，同时 2/3/4/5 不退步。
