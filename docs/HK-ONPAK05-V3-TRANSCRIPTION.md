# 安柏苑 05 室 —— v3 转录（官方向量 PDF 的印刷尺寸）

**v1/v2 的几何全部作废。** 它们是在一张 1600×1200、69 KB 的付费商品预览缩略图上做
"摄影测量"得来的：自己假定形状、自己量像素、自己定比例尺（还两轴各自定标）。
结果凭空造出一条图上根本不存在的"西侧竖带"当客厅，
**引擎就把沙发和茶几摆到屋外** —— 而那张图看起来完全正常。

v3 的唯一来源是**官方向量 PDF 上的印刷毫米尺寸**，一个像素都不用猜。

| 步骤 | 做法 |
|---|---|
| 1 | `Sales-Brochure-On-Pak.pdf` 第 26 页（2/F-9/F 平面图），矢量图，A3 |
| 2 | 比例尺由图上**印刷的比例尺条**独立标定：0→5 m = 70.86 pt ⇒ **1 pt = 70.5617 mm（1:200）** |
| 3 | `mutool draw -F trace` 导出矢量，按颜色分层：橙 `.912 .26 .055` = 尺寸标注层、黑 `0 0 0` stroke = 墙线、cyan/green fill = 房间填充 |
| 4 | 整层绕 **13.5°**（右翼倾角）转正后，自动找尺寸链的 tick 位置；**tick 间距就是印刷的 mm** |
| 5 | 用 tick 间距反查图上印的数字，逐条互相印证 |

生成器：`services/floorplan/make_hk_onpak05.py` → `out/plan_hk_onpak05.json`
（旧的那个已改名 `DEPRECATED_make_hk_onpak05_v2_pixel_measured.py` 并在 import 时直接 SystemExit）

## 核对

- 转录后室内净面积 **37.16 m²**；在官方图（转正后）上按颜色量得 **37.6 m²**，差 **1.2 %**。
- 商品页 493 平方呎 = 45.8 m² 实用面积；45.8 × 0.81 = 37.1 —— 差额正好是内墙 + 外墙一半。
- `out/ref/onpak05_v3_overlay_on_official.png`：v3 的墙线/门窗直接叠在官方图上，
  全屋偏差 ≤ 100 mm（浴室、厨房、饭厅凹位、入户门、中央 320 承重墙全部对上）。
- `out/ref/onpak05_v3_vs_official.png`：左 = 由印刷尺寸重建的图，右 = 官方图。
- `out/ref/onpak05_official_axis_aligned.png`：官方图转正 13.5° 后的线稿（墙黑、室内棕）。

## 三个必须记住的坑

1. **`mutool trace` 对 `fill_path` 输出的 transform 不含外层旋转**
   （同一张图上 `stroke_path` 的 transform 却是对的）。照它画出来的房间填充是
   "剪切过的平行四边形"：看起来像房间、面积也对，但角度整整差 13.5°，
   叠加到渲染出的位图上才看得出来。**凡是矢量解释，必须用渲染位图核对一次。**
2. 图上 `1235` **不是**浴室的宽度 —— 它是浴室**南边另一条链**上的数字。
   浴室宽度是 BATH 上方那条链的 `2030`。第一版差点把浴室做成 1245 宽，
   面积从 2.98 m² 缩到 1.83 m²（1.8 m² 的浴室放不下淋浴间）。
3. **一张画得漂亮的图不能证明它是对的。** v2 的叠图看起来"对得上"，
   因为比例尺本来就是拿同一批墙拟合出来的 —— 一致的比例尺错误，
   在叠图上完全隐形。真正的判据是**独立的第二来源**（这里是印刷比例尺条 + 尺寸链）。
