## 案例 1（主基准）：油塘 曦臺 1 座 31 樓 F 室

| | |
|---|---|
| 图纸 | Design Layout Plan／「度呎後 - 電圖」，日期 2021-01-16 |
| 出图方 | 新雅致室內設計有限公司 NEW ELEGANT DESIGN（版权声明署名 SPACE DESIGN LIMITED） |
| 取得处 | https://www.acdesign.com.hk/wp-content/uploads/2026/05/unit_112_floorplan_28_G3C3.jpg |
| 分辨率 | 1600 x 1130 |

**为什么它合格**

1. 有**毫米标注**：1840 / 1965 / 1800 / 1450 / 1435 / 1390 / 1427 / 1382 / 1200 / 615 /
   600 / 650 / 560 / 500 / 460 / 450 / 342 / 2067 / 2680 / 2972(淨) / 3142 —— 不需要靠画素估比例尺。
2. 有**层高**：2790H / 3300H / 2785H（客厅挑高 3.3m）。
3. 有**设计后的家具**：主人房 4'6"x6'3" 床、書房「上牀下書枱」（阁楼床 + 书桌）、
   衣柜、廁所（坐廁已画）、廚房「不動全保留」、戶外櫃、阁楼（閣仔）。
4. 有**本次要修的那类坑**：窄走廊、结构墙（黑色实心）、门洞与开启方向、
   床与书桌共用一个房间、挑高夹层。

**已知的转录难点（诚实记录）**

- 左半幅与右半幅的绘图比例可能不同（粗测 8.4 vs 7.4 mm/px），
  转录前要用图中标注做双向校验，不能整张图用一个比例尺。
- 单位含挑高夹层（阁仔），是 2D 引擎的边界情况，先只做地面层。

## 「合理」的判据清单（本次训练的目标）

用户点名的四条 + 此前实际踩过的坑，全部列在这里，作为 benchmark 的通过项。

### A. 用户点名
1. 床不可以挡门
2. 沙发要对着电视（电视柜存在时）
3. 家具不可以挡走廊（从大门要走到每件家具前面）
4. 厕所必须有马桶（essential 品类不许被「优化掉」）

### B. 项目此前踩过、必须不再复发的坑
5. 求解器用「不摆」来消灭硬伤 → 漏放罚分必须压倒一切
6. 小房间门走道吃掉 69% 楼面 → 走道面积上限 + 深度下限
7. L 形房间被家具掐断连通
8. 衣柜正好压在浴室门口
9. 家具摆到墙外 / 压在固定障碍（服务核心、柱）上
10. 漏放「定义房间功能」的家具（床／马桶／灶台／沙发）
11. 家具重叠加叠
12. 衣柜/雪柜正前方打不开门
13. 平面图上的房名与房间功能对错（厨房↔浴室互换）
14. 渲染用的户型与家具配对错（拿 A 的墙配 B 的家具）

### C. 本次要新增（审计发现的根因）
15. 功能关系：餐椅必须靠近它那张餐桌（现在完全没有这条规则）
16. 成对家具要成对（躺椅、扶手椅）
17. 朝向不许退化成「朝向房间代表点」（现在 11 张椅子朝同一个任意点）
18. 关系不可以在批量阶段被跳过

## 落实顺序

1. 把案例 1 转录成 plan JSON，并用「图中标注」双向校验比例尺（不靠单一比例尺）。
2. 写 `scripts/bench_hk.py`：对每个案例跑引擎，逐条检查上面 18 项，输出通过率表。
3. 先跑基线，记录引擎现在实际错在哪几条 —— 用数字说话。
4. 按审计里的顺序改引擎，每改一次重跑 benchmark。
5. 把首次「改不动」的地方（饱和点）作为**明显瓶颈**报告。
